# Plan de Mejora de UX para Simulador del Mundial 2026

## Objetivo General
Implementar mejoras de accesibilidad, usabilidad y rendimiento basadas en las recomendaciones del análisis UX, enfocándonos en cuatro áreas clave para elevar la calidad del producto a estándares profesionales.

## 1. Reemplazar Divs Interactivos con Botones Semánticos y Atributos ARIA

### Contexto
Actualmente, varios elementos interactivos usan `<div>` con `onClick`, lo cual viola estándares de accesibilidad y semántica HTML. Los lectores de pantalla no reconocen estos como elementos interactivos.

### Elementos Identificados
- `team-row` (src/app.jsx:385): Selección de equipos en grupos
- `third-c` (src/app.jsx:421): Selección de mejores terceros
- `m-tm` (src/app.jsx:469, 480): Selección de ganadores en partidos
- Botones de icono sin `aria-label` (ej. stats-btn)

### Plan de Implementación
1. **Cambiar elementos HTML**: Reemplazar `<div>` por `<button type="button">` manteniendo clases y manejadores de eventos
2. **Agregar atributos ARIA**: 
   - `aria-label` descriptivo para botones de icono
   - `aria-pressed` para elementos toggle si aplica
3. **Ajustar estilos CSS**: Asegurar que los nuevos botones mantengan apariencia visual (quitar estilos específicos de div si es necesario)
4. **Pruebas**: Verificar navegación por teclado y compatibilidad con lectores de pantalla

### Riesgos y Consideraciones
- Cambios visuales mínimos requeridos
- Posible impacto en estilos de foco existentes
- Necesidad de mantener funcionalidad onClick intacta

## 2. Implementar Estilos Focus-Visible y Navegación por Teclado

### Contexto
Los elementos interactivos carecen de indicadores de foco visibles, dificultando la navegación por teclado para usuarios con discapacidades motoras.

### Estado Actual
- No hay estilos `:focus-visible` definidos
- Algunos elementos pueden no ser enfocables por defecto

### Plan de Implementación
1. **Definir estilos base**: Agregar reglas CSS para `:focus-visible` en elementos interactivos
   ```css
   *:focus-visible {
     outline: 2px solid var(--lime);
     outline-offset: 2px;
   }
   ```
2. **Personalizar por componente**: Ajustar estilos específicos para botones, tarjetas, etc.
3. **Asegurar accesibilidad**: Verificar que todos los elementos interactivos sean alcanzables con Tab
4. **Pruebas**: Navegación completa por teclado en todas las fases

### Beneficios Esperados
- Cumplimiento WCAG 2.1 AA
- Mejor experiencia para usuarios de teclado
- Indicadores visuales claros de elementos activos

## 3. Agregar Consultas de Medios Prefers-Reduced-Motion a Animaciones

### Contexto
Las animaciones no respetan la preferencia del usuario `prefers-reduced-motion`, afectando a personas con condiciones como vértigo o migrañas.

### Animaciones Identificadas
- `.a-up` (fadeUp)
- `.pulse-glow`
- `.a-crown` (crownFloat)
- `.champ-burst` (champBurst)
- `.champ-spark` (sparkDrift)
- `.connector-line:after` (lineSweep)

### Plan de Implementación
1. **Identificar animaciones**: Mapear todas las animaciones en CSS
2. **Agregar media queries**: 
   ```css
   @media (prefers-reduced-motion: reduce) {
     .animation-class {
       animation: none;
     }
   }
   ```
3. **Variantes reducidas**: Para animaciones complejas, proporcionar versiones simplificadas
4. **Preservar transiciones esenciales**: Mantener hover/focus states

### Consideraciones
- Animaciones de entrada pueden ser completamente removidas
- Transiciones de hover deben mantenerse por retroalimentación visual

## 4. Agregar Tooltips u Onboarding para Fases Complejas

### Contexto
El flujo del simulador puede ser confuso para usuarios nuevos, especialmente las reglas de mejores terceros y selección de ganadores.

### Fases a Mejorar
- **Fase de Grupos**: Explicar selección de 3 clasificados por grupo
- **Mejores Terceros**: Clarificar criterios de selección de 8 equipos
- **Eliminatorias**: Guiar sobre selección de ganadores

### Opciones de Implementación
1. **Tooltips contextuales**: Aparecen en hover/foco de elementos clave
2. **Modal de onboarding**: Muestra al inicio con explicación del flujo
3. **Texto de ayuda inline**: Descripciones cortas junto a títulos

### Plan Recomendado
1. **Implementar tooltips**: Usar biblioteca ligera o componente custom
2. **Onboarding condicional**: Mostrar solo en primera visita (localStorage)
3. **Contenido claro**: Explicaciones concisas en español
4. **Opcional de dismiss**: Permitir saltar onboarding

### Métricas de Éxito
- Reducción en tiempo de comprensión del flujo
- Menos confusión reportada por usuarios
- Mejor completion rate de fases

## Cronograma Estimado
- **Fase 1**: 2-3 horas (cambios HTML/ARIA)
- **Fase 2**: 1-2 horas (estilos focus)
- **Fase 3**: 1 hora (media queries animaciones)
- **Fase 4**: 3-4 horas (tooltips/onboarding)

## Pruebas Post-Implementación
- Navegación por teclado completa
- Compatibilidad con lectores de pantalla (NVDA, JAWS)
- Validación automática con axe-core o similar
- Pruebas de usuario para feedback

## Dependencias
- Ninguna biblioteca externa requerida inicialmente
- Posible adición de react-tooltip para fase 4 si se elige tooltips avanzados
